**Message:**
> initial module: view-inherit unhides Confirm on Local Credit RFQs
>
> The Studio inherit on purchase.order.form (view id 2409, priority
> 95) gates //header/button[@name='button_confirm'] with two clauses
> that stay TRUE for the entire Local Credit lifecycle:
>     x_studio_receive_status == 'Pending'
>     x_studio_pr_update      == True
> Both clauses only clear when the user clicks two separate Studio
> buttons in sequence ("Receive Quotation" then "Update PR").
> Symptom on Clear-DB record PO-00070 (Local, credit-terms, from
> approved PR/2026/00057): Confirm Order button is invisible even
> though state='sent' and the RFQ is otherwise ready to promote.
> Both gates are now redundant. BugFix-Purchase v0.7 already:
>   - chains the "Update PR Status in PO" server action (id 991)
>     into button_confirm, so pressing Confirm performs the PR sync
>     in the same transaction (removes the reason for the
>     pr_update gate)
>   - hides the manual "Update PR" button via
>     purchase.order._get_view (leaving the confirm gate would
>     surface a dead-end: Confirm hidden, Update PR hidden)
> The receive_status gate exists to force uploading a supplier
> quotation PDF before Confirm. That is an Import (LC) business
> rule, not a Local Credit rule -- Local vendors are on account
> terms and the PDF is not part of the paper trail.
> This module adds an ir.ui.view inherit at priority 200 that
> rewrites the invisible expression on button_confirm to drop the
> two clauses, preserving every other gate verbatim (state, so_pr,
> header charges, subcontracting).
> No Studio record is edited; view 2409's arch_db is untouched.
> The rewrite runs on the merged arch after the Studio inherit.
> If bugfix_purchase or the Studio customization is ever removed
> the install still succeeds -- the target is the standard
> purchase.purchase_order_form, and the rewrite becomes a no-op
> because the dropped clauses would not be there to begin with.
> Depends on bugfix_purchase so the Update PR chaining is present
> when this module relaxes the gate.
> Only the state='sent' variant of button_confirm is rewritten.
> The Studio view carries a second [2]-indexed variant for
> state='draft'; the reported bug is on 'sent' so 'draft' is
> untouched. If draft POs also need the relaxed gate a follow-up
> xpath can target //header/button[@name='button_confirm'][2].
